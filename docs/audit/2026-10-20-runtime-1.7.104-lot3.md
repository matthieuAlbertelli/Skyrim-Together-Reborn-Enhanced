## Admission and validation boundary

The finite table now has **18/18 mandatory static qualifications**: ten
ExactSource from lot2 plus eight ExactBinary from this lot. Consequently the
unchanged expression `NativeAdmissionReady(NativeContracts)` evaluates true.
There is no literal true assignment/override/bypassed-ID success. Removing any
mandatory evidence, replacing required binary proof with source-only proof,
demoting scope, duplicating IDs or truncating the table must still fail tests.
Only ResetMain, GrabRelease, FinalAppearance and LocalSeating use the narrow
dual-exact-version helper. O02/O03/D01 stay unavailable on1.7; vanilla menu
fallback and Valen's existing content/progression policy are preserved.

Before mapping/initializers, executable admission independently requires exact
1.7.104.0 Steam PE, valid matching AL, SKSE resource0.2.3.1 and native
capabilities. The per-launch DLL load/export check occurs after STRE hook
commit, before game entry; the static receipt inspects that export without
loading the DLL. The gate is a compiled qualification record, **not a
per-launch hash allowlist**; these receipts qualify only the exact material
above. Different same-version EXE/SKSE/AL bytes require requalification before
the controlled experiment.

The final build/test results and compiled source identity are recorded in
