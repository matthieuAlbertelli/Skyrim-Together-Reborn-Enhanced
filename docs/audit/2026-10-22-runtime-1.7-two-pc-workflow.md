### Implemented correction

In `Stre.Runtime17Dev.psm1`, `Get-R17Reference` keeps the pinned manifest and
tracked path inventory as scope, without requiring historical Git/content bytes.
`Add-R17InstalledContent` captures only managed paths from configured A Data,
using independent copies, source stability checks and per-file provenance.
`Get-R17DeploymentRows` combines them with fresh build-owned native/UI paths;
`Assert-R17Package` checks the frozen set. There is no Git fallback or CK import.

`Get-R17Preflight` / `Get-R17Plan` record identical/replace/create states instead
of blocking initial differences. `Get-R17FileState` distinguishes missing paths,
access denial and IO failures. `Backup-R17Target`, `Set-R17Payload`,
`Restore-R17Staging` and `Invoke-R17Workflow` now use the combined manifest,
independent scoped backups, unlink-before-copy, post-copy verification, per-file
journals and per-PC phase/results. Verify retains source identity and both actual
installation checks. Failures never become an overall PASS.

RestoreStaging prepares each PC's pre-run **installed** bytes in its staging for
human Vortex redeployment; the different original staging bytes remain backed up.
This avoids claiming recovery by redeploying an already divergent original staging.
Both backup sets are checked before either restoration. New receipts use schema 2;
native-only schema-1 receipts are explicitly rejected. No real-run receipt needed
migration in this inspection.

The xmake install hook was inspected: it writes generated UI and CEF/Discord to
the selected fresh distribution, not Data or GameFiles content. Snapshot assembly
happens afterward. Native/content namespace fences reject collisions. Canonical
`config/STServer.ini`, its optional staging absence and required installed Better
Grabbing policy are preserved. Shipped main-menu presentation/localization INIs
are explicit content assets, not server configuration. External dependencies,
personal files and all paths outside the manifest, including old UI, are not copied
or purged. This supersedes the initial native-only preflight policy above.
